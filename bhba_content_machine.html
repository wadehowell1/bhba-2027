🛈 Why this build stops at the approval gate

The blocking constraint: this repository is static HTML served from GitHub Pages. There is no server-side runtime. A publishing connector needs OAuth client secrets and long-lived platform access tokens. In a static page, every one of those is publicly readable by anyone who views source — and a leaked social token means someone else can post as BHBA, everywhere. The same applies to an AI provider key: it would be a public, billable credential.

So sections 15 and 16 of the build guide (publishing engine, platform connectors) are deliberately not implemented. That is the guide's own rule — "all publishing calls happen server-side only" — and this repo has no server side to put them in.
What that costs you: about 30 seconds per post. Everything up to the gate is automated — analysis, ten platform adaptations, captions, hashtags, format specs, safe zones, approval, scheduling, memory. You paste the finished pack. That's the honest version, and it's still the large majority of the work.

To unlock automated publishing later

It needs a backend (Cloudflare Worker, Supabase Edge Function, or a small Node service) that holds the tokens encrypted server-side, exposes only publish(versionId) to this page, checks the idempotency key before every attempt, and enforces the same approval gate server-side rather than trusting the browser. At that point the connect-src 'none' lock in this file's CSP is relaxed to that one origin and nothing else — a deliberate, reviewable change.
