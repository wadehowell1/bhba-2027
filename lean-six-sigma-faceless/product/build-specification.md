# Build Specification

This business has **two** product types, and the doc's framework treats them
differently for good reason:

- **Digital product** (Rungs 0–2) — modules, files, templates, bonuses, delivery.
- **Service** (Rung 3) — deliverables, onboarding, fulfilment, reporting, renewal.

Both specs are below, plus the light software surface needed to sell them.

> **Build order is not the order below.** See §4 — build Rung 0 and 1 first, Rung 2
> last, and only after the validation gates pass.

## 1. DIGITAL PRODUCT SPEC

### 1.1 Rung 0 — The 60-Minute Waste Walk *(free)*

| | |
|---|---|
| **Files** | 1 guide (PDF + web page), 1 worksheet (Google Sheet + printable PDF) |
| **Delivery** | Email opt-in → immediate delivery email with links |
| **Build effort** | 🔶 ~8–12 hrs |
| **Status** | ✅ Content written — `../marketing/lead-magnet/waste-walk.md` |

**Design constraints:** completable in 60 minutes by someone with no lean knowledge;
printable, because it is used walking around, not at a desk; ends with one ranked
list and one decision; genuinely useful if they never buy anything.

### 1.2 Rung 1 — The Small Shop Lean Kit *($49)*

**Nine files.** Each ships in three states, and the middle one is the actual product:

1. **Blank** — to use
2. **Filled-in example** — a fictional 11-person business, *clearly labelled as an
   illustrative example, not a real client*
3. **One-page how-to** — what it is for, when to use it, what "done" looks like

| # | File | Format | Notes |
|---|---|---|---|
| 1 | Process Map (one page) | Sheet + PDF | Max 12 steps; no swimlanes |
| 2 | Waste Walk Worksheet (extended) | Sheet + PDF | Superset of the free version |
| 3 | Standard Work sheet | Doc + PDF | Photo slots; written for the doer |
| 4 | Daily Huddle board + agenda | Sheet + PDF | 10-minute script included |
| 5 | Problem One-Pager | Doc + PDF | An A3, not called one on the cover |
| 6 | 5 Whys / root cause sheet | Doc + PDF | Worked small-business example |
| 7 | Job Setup Checklist | Doc + PDF | Error-proofing, plain language |
| 8 | Improvement Tracker | Sheet | One tab. Not a PMO |
| 9 | **The Translation Guide** | Doc + PDF | Lean term → plain English → do you ever need to say it |

**Why file 9 matters more than it looks:** it is the differentiator made tangible, it
serves the practitioner's credibility need directly, and it is the single most
shareable asset in the Kit — which makes it a referral engine as well as a product.

| | |
|---|---|
| **Delivery** | Checkout → automatic delivery email → access page with "Make a copy" links + a zip of PDFs |
| **Bonus** | Kit → course discount ($49 credited against Rung 2) |
| **Build effort** | 🔶 ~20–30 hrs |
| **Updates** | Buyers get all future versions free — a real reason to buy, and cheap to honour |

### 1.3 Rung 2 — Fix One Process *($349)*

**Four modules, one per week.** Each ends with a **completed artifact for their
business**, not a completed lesson.

| Wk | Module | Lessons | Artifact they finish with |
|---|---|---|---|
| 1 | **Pick and measure** | Choosing the right first process (and which to avoid); measuring what happens now; the one-page map | Baseline number + process map |
| 2 | **Find the real cause** | The Waste Walk on your process; separating symptoms from causes; getting the team to tell you the truth | Ranked, evidenced cause list |
| 3 | **Design and pilot** | Designing the new way *with* the person who does the job; writing standard work; error-proofing the top failure; running a one-week pilot | Standard work + pilot results |
| 4 | **Make it stick** | The daily ten minutes; what to do when it slips; re-measuring; picking the next process | Huddle rhythm + before/after |

**Per lesson:** 5–9 min video (screen + diagram, no face — consistent with the
faceless brand), transcript, the artifact template, and one worked example.

**Plus a troubleshooting section** — the five stalls, written from the SME lean
research: no time in week 2, the team thinks it is about layoffs, picked too big a
process, no data to measure with, and the owner doing it alone instead of with the
doer. *(These five come from documented SME failure modes, not from guesswork.)*

| | |
|---|---|
| **Platform** | 🔶 Hosted course platform (Podia / Teachable / Gumroad). **Do not build one.** |
| **Build effort** | 🔶 ~80–120 hrs — **the largest investment in the business** |
| **Gate** | ⛔ Do not start until Gates 2–4 pass |

## 2. SERVICE SPEC — Rung 3, The 90-Day Desk

### 2.1 Deliverables

| # | Deliverable | When |
|---|---|---|
| 1 | Kick-off diagnostic — top 3 costly processes, ranked, with rough numbers | Week 1 |
| 2 | 6 × 60-min fortnightly working sessions | Weeks 2–12 |
| 3 | Process 1 fixed — we lead | Weeks 2–6 |
| 4 | Process 2 fixed — **they lead, we coach** | Weeks 7–11 |
| 5 | Running huddle rhythm their team uses | From week 3 |
| 6 | Before/after measure on both processes | Weeks 6 and 11 |
| 7 | 90-day handover plan | Week 12 |

**Deliverable 4 is the one that matters.** If we fix both processes ourselves, we have
sold dependency. The engagement succeeds when they run the second one.

### 2.2 Onboarding

| Day | Step |
|---|---|
| 0 | 20-min fit call — qualify **out** as much as in |
| 0 | Explicit no-fit criteria: wants headcount cuts; under 5 or over 50 staff; no repeatable process; owner will not attend sessions |
| 1 | Agreement + payment (⚠️ needs legal review) |
| 2 | Welcome pack: what happens, what we need, what we will ask of their team |
| 3–5 | Diagnostic — walk the work, talk to the people doing it |
| 7 | Diagnostic readout + the three candidate processes, ranked |
| 7 | **They choose.** Not us |

**Qualifying out is a feature.** The research says lean fails without owner commitment
and employee involvement; taking a client whose owner will not attend is selling a
known failure.

### 2.3 Fulfilment rhythm

Fortnightly 60-minute working session. Standing structure:

1. What changed since last time (10 min)
2. What is stuck (10 min)
3. **Work on the actual thing together** (30 min) — not a status meeting
4. What happens before next time, who does it (10 min)

Between sessions: async check-in on one channel (email or a shared doc). ⚠️ Response
time is a **commitment** — set it deliberately (suggested: 1 business day) and put it
in the agreement.

### 2.4 Reporting

One page, fortnightly. Process, baseline, current, what changed, what is next, what we
need from you. Not a slide deck. If it takes more than 15 minutes to write, it is too
long to read.

### 2.5 Renewal

Renewal is offered **only** when deliverable 4 succeeded — i.e. they proved they can
run one themselves. Options: a second 90 days on a new area, or a light monthly
check-in (⚠️ price not set — depends on Test 2).

> **Do not build renewal into the pitch.** Selling a 90-day engagement while planning
> for month 12 is how consultants create the dependency this method is supposed to
> remove.

## 3. SOFTWARE SURFACE (deliberately minimal)

We are not building software. We are assembling the smallest stack that can sell and
deliver.

| Need | Approach | ⚠️ |
|---|---|---|
| Marketing site | Static HTML/CSS — `../website/` | Built |
| Email capture | Form → email platform API | Key in env var, never in client JS |
| Email delivery | ESP (ConvertKit / MailerLite / Resend) | Choice pending |
| Payments | Stripe Checkout or Gumroad/Podia hosted | **Never** handle card data ourselves |
| Product delivery | Hosted platform or emailed links | Choice pending |
| Booking | Cal.com / Calendly | — |
| Analytics | Privacy-friendly (Plausible / Fathom) | Placeholder in site |

### Security and secrets rules (non-negotiable)

- **No API keys, tokens or secrets in client-side JavaScript, ever.** The site is
  static; any key-bearing call goes through a serverless function or the ESP's own
  hosted form.
- All secrets in environment variables. `.env` is git-ignored; `.env.example` is
  committed with **placeholder values only**.
- Never commit a real key, even briefly — assume anything pushed is public forever.
- Payments run through a PCI-compliant hosted checkout. We never see a card number.
- ⚠️ Privacy policy, cookie handling and GDPR/CCPA obligations need human review
  before collecting a single email address.

## 4. BUILD ORDER

```
NOW ──────────────────────────────────────────────────────────
 1. Waste Walk content         ✅ done
 2. Website + landing page     ✅ done
 3. Email capture + delivery   ← wire up (needs ESP choice)
 4. Kit — the nine files       ← ~20–30 hrs, needed regardless

GATE: Tests 1–3 ─────────────────────────────────────────────
 5. Sell the Kit (Test 5)
 6. 15 discovery conversations (Test 4)  ⛔ GATE 2

GATE: Gates 2–3 pass ────────────────────────────────────────
 7. One pilot engagement (Test 6)        ⛔ GATE 4

GATE: Gate 4 passes ─────────────────────────────────────────
 8. Fix One Process course     ← the 80–120 hr build, LAST
```

**The logic:** everything before the first gate is cheap and needed no matter what the
tests say. Everything after is expensive and conditional. The course is the biggest
build and the last one — because it is the piece most likely to be wasted if the
earlier bets are wrong.
